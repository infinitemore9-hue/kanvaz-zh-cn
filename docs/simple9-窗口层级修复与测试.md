# simple.9：切换软件后正常退到后面

日期：2026-11-04。基础版本 9.8.2，非官方本地修复版标记 9.8.2-cn.simple.9。本轮未推送 GitHub。

## 原因与修复

之前默认开启“始终置顶”，旧版迁移也曾强制开启。只要置顶开启，窗口失去焦点后会在 120、700、2000 毫秒保持最上层，另有 500 毫秒周期检查；因此切换到其他软件后仍会遮挡。这属于原来的强制置顶策略。

本版默认使用普通窗口层级。点击或切换到其他软件后，由系统正常安排前后顺序。普通模式下不触发置顶计时器和抬升操作。

第一次从旧设置升级到本版，会关闭旧设置中的置顶并写入迁移标记；不会每次启动都重置。此后在设置中手动开启“窗口始终置顶（默认关闭）”，仍会保留选择并跨重启生效。手动置顶以及专门的置顶/参考锁定模式仍然会覆盖其他软件，这是这些模式的用途。

设置路径：完整界面 → 设置 → 画布与输入 → 窗口始终置顶（默认关闭）。旧版也可以先关闭原来的“窗口始终置顶（默认开启）”，无需等待升级。

## 启动新版本

解压完整便携包，保存好旧版本中未保存的画板，然后关闭旧窗口，启动新文件夹里的“Kanvaz 中文版.exe”。请保留同目录其他文件。单独打开新版本不会改变仍在运行的旧进程；旧窗口若仍开启置顶，仍可能挡住新窗口。

## 实际验证

使用隔离测试配置，未更改用户当前配置或关闭用户窗口：

- 预置旧版 alwaysOnTop=true，升级后设置关闭，并确认原生窗口 isAlwaysOnTop=false。
- 启动另一个独立 Electron 进程，创建相同位置的重叠普通窗口。切换焦点后等待 2.9 秒，使用 Windows GetWindow 检查两个原生窗口的相对 Z 顺序，以及 GetForegroundWindow 对应的进程（桌面操作可使前台转到其他外部软件，因此不强制前台必须是测试辅助进程）。另一个窗口保持在 Kanvaz 上方，前台属于 Kanvaz 以外的进程。
- 手动开启置顶后确认原生标志变为 true，重启同一配置后仍为 true，证明迁移只执行一次。
- 关闭置顶后进入专门置顶模式，退出后恢复普通窗口。
- 全新配置默认原生置顶标志为 false。

上述测试通过。相对窗口层级测试不等于逐一测试 Photoshop、Illustrator、所有全屏软件或所有 Windows 版本。初次点位测试受其他现存窗口遮挡，最终采用原生相对 Z 顺序和前台进程验证，没有隐藏或关闭现存用户窗口。

Windows 本机版本 10.0.26100，Electron 44.4.3。交付为未签名 Windows x64 目录式便携 ZIP。构建、validate、新功能回归及原生层级测试日志随包提供。独立 Chrome/MCP 依赖缺失的检查仍为 SKIP，不能算作通过。
